1. Skill이라는 말이 가리키는 것

논문마다 Skill이 뜻하는 바가 다릅니다. 여기서는 “특정한 일을 해내는 방법이 저장된 형태”로 넓게 잡았습니다.

논문 Skill의 형태 누가 만드나
ReAct 프롬프트 속 풀이 예시 (자연어) 사람이 작성
Reflexion 실패 후 쓴 반성문 (자연어) LLM이 생성
Voyager 검증된 실행 함수 (코드) LLM이 생성
VPT 영상으로 학습한 신경망 가중치 학습
STEVE-1 목표에 조건화된 신경망 가중치 학습

ALFWorld는 환경을 제공한 논문이라 표에서 뺐습니다.

왼쪽으로 갈수록 사람이 읽고 고치기 쉽고, 오른쪽으로 갈수록 사람과 같은 조건(화면과 마우스)에서 움직입니다. 둘을 함께 갖춘 논문은 이 중에 없습니다.

표에서 policy 역할을 하는 것은 각각 Qwen(프롬프트를 받은 LLM), GPT-4(코드 생성기), VPT와 STEVE-1의 신경망입니다. Policy는 “지금 본 것으로 다음 행동을 정하는 것”을 가리키는 말이고, IDM이나 MineCLIP은 policy가 아닙니다.

3. 형태가 바뀌어도 남는 것 — 언어–행동 불일치 네 가지

ALFWorld 실험에서 실패를 네 유형으로 나눴습니다. 같은 유형이 다른 논문에서 어떻게 나타나는지 옮겨 보았습니다.

유형 ALFWorld (직접 실험) Voyager VPT STEVE-1
1. 지시문의 표현 ↔ 행동 put/move로 45% → 80%, 환경이 변환해 주면 100% 없는 함수 호출이 실행 에러로 드러남 지시 자체가 없음 “get dirt” 9.2 vs 자세한 지시문 26.7
2. 모델의 상식 ↔ 환경 규칙 일상의 move와 환경의 move가 다름 게임에 없는 아이템, 맞지 않는 연료 해당 없음 확인되지 않음 → 실험 대상
3. 가리키는 대상 cloth를 towel로 착각 드묾 (상태를 텍스트로 정확히 받음) 해당 없음 소 대신 다른 동물을 때림
4. 실패 원인 ↔ 설명 반성문 95개 중 원인을 짚은 것 2개 피드백과 검증으로 보완 수단 없음 수단 없음

읽어 낸 것은 세 가지입니다.

  • 1번과 3번은 Skill의 형태와 상관없이 남습니다. 자연어든 코드든 가중치든, 그 skill을 고르고 대상을 지정하는 것은 언어입니다.
  • 4번을 구조적으로 보완한 것은 Voyager뿐입니다. 환경이 실패 이유를 말해 주도록 설계했습니다.
  • 화면을 보고 움직이는 모델(VPT, STEVE-1)에는 실패를 언어로 다루는 단계가 아예 없습니다.

4. 헷갈리기 쉬운 개념 세 쌍

읽는 동안 자주 섞였던 것들입니다.

비교 차이
Pseudo-labeling vs Hindsight relabeling 앞은 행동 라벨을 모델이 추정해 붙임(틀릴 수 있음). 뒤는 목표 라벨을 규칙으로 정함(실제 도달한 장면이라 틀리지 않음)
Hallucination vs Goal misgeneralization 앞은 없는 것을 지어냄(구리 검). 뒤는 실제로 있는 다른 것을 목표로 착각함(소 대신 돼지)
Skill library vs Reflexion의 메모리 앞은 성공한 코드를 저장해 다른 일에도 씀. 뒤는 실패를 돌아본 글이고 그 게임에서만 씀

5. 다음 실험 — STEVE-1에서 같은 일을 다른 문장으로 시키기

ALFWorld에서는 동사 하나가 성공률을 바꿨습니다. 화면을 보고 마우스를 움직이는 모델에서도 같은 일이 일어나는지 직접 확인해 보려고 합니다. STEVE-1 논문이 이미 사례를 보고했으므로, 같은 조건을 더 촘촘히 나눠 보는 실험입니다.

항목 설계
질문 같은 일에 대해 지시문 표현을 바꾸면 행동과 성과가 얼마나 달라지는가
과제 나무 수집, 흙 수집. 논문에서 안정적으로 수행된 짧은 일
조건 과제마다 3–4개: 짧은 동사(“chop a tree”) / 같은 뜻의 다른 표현(“get wood”, “collect logs”) / 자세한 지시문 / 목표 이미지
반복 조건마다 5–10판, 한 판에 1–2분, 월드 시드 고정
기록 끝났을 때 인벤토리의 나무 · 흙 개수, 플레이 영상, 대상을 착각한 사례

Voyager와 VPT는 실행하지 않습니다. Voyager는 유료 API와 게임 라이선스가 필요하고, VPT는 지시를 받지 않아 이 질문을 던질 수 없습니다. STEVE-1이 VPT를 포함하고 있으므로 STEVE-1 실행으로 대신합니다.

6. 정리

  • Skill은 자연어, 코드, 가중치로 표현될 수 있고, 형태에 따라 만드는 법 · 저장하는 법 · 고르는 법 · 검증하는 법이 달라집니다.
  • 형태가 달라도 skill을 고르는 것은 언어이고, 그 언어가 행동과 어긋나는 문제는 계속 나타납니다.
  • 다음 글은 STEVE-1을 직접 돌린 결과입니다.
