## 1. 한눈에

| 항목      | 내용                                                            |
| --------- | --------------------------------------------------------------- |
| 모델      | STEVE-1 공개 가중치 (`CraftJarvis/MineStudio_STEVE-1.official`) |
| 실행 도구 | [MineStudio](https://github.com/CraftJarvis/MineStudio) 1.1.6   |
| 장비      | 클라우드 GPU (H100 1장)                                         |
| 평가 방식 | 논문 Appendix F.2 · Table 3                                     |
| 규모      | 지시문 2개 × 10판 = 20판, 약 38분                               |
| 결과      | 흙 10.7개 (논문 9.2), 나무 5.2개 (논문 약 8.5)                  |

학습은 하지 않았습니다. 공개된 가중치를 그대로 불러와 게임을 시키고 결과만 셌습니다.

## 2. 실행 환경

STEVE-1 원본 저장소 대신 MineStudio를 썼습니다. 시뮬레이터, 모델, 가중치 내려받기를 한 패키지로 묶어 둔 도구라 설치가 간단합니다.

| 구성      | 설정                                     |
| --------- | ---------------------------------------- |
| Python    | 3.10 (conda)                             |
| Java      | 8 (OpenJDK). 마인크래프트 실행에 필요    |
| 화면      | `xvfb-run`으로 가상 디스플레이 사용      |
| 관측 크기 | 128 × 128                                |
| 실행      | `nohup`으로 백그라운드 실행, 로그는 파일 |

모니터가 없는 서버라 게임 화면을 그릴 곳이 없습니다. `xvfb-run`은 가짜 모니터를 만들어 주는 명령입니다.

한 판을 돌리는 코드의 뼈대는 아래와 같습니다.

```python
policy = SteveOnePolicy.from_pretrained("CraftJarvis/MineStudio_STEVE-1.official").to("cuda").eval()
env = MinecraftSim(obs_size=(128, 128), preferred_spawn_biome="forest", callbacks=[])

env.env.seed(seed)
obs, info = env.reset()
cond = policy.prepare_condition({"cond_scale": 6.0, "text": "chop a tree"})  # 판마다 한 번
memory = None
for _ in range(3000):
    x = {"image": torch.from_numpy(obs["image"])[None, None].to("cuda"), "condition": cond}
    action, memory = policy.get_action(x, memory, input_shape="BT*")
    action = {k: v[0][0] for k, v in action.items()}
    obs, reward, terminated, truncated, info = env.step(action)
```

## 3. 막혔던 곳 세 가지

| 증상                                | 원인                                                                                      | 대응                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 백그라운드 실행이 시작하자마자 종료 | 게임 엔진이 임시 저장소에 있어 서버를 멈추면 사라짐. 다시 받을지 묻는 `Y/N` 입력에서 멈춤 | `MINESTUDIO_DIR`을 지워지지 않는 저장소로 지정하고 엔진을 미리 내려받음 |
| 13번째 판에서 `TimeoutError`        | 새 월드를 만드는 `env.reset()`에서 게임이 응답하지 않음                                   | 오류가 나면 게임을 닫고 다시 만들어 그 판만 재시도 (최대 3회)           |
| 중간에 끊기면 결과가 사라질 위험    | 결과를 마지막에 한 번에 저장                                                              | 한 판이 끝날 때마다 CSV에 한 줄 기록, 다시 실행하면 끝난 판은 건너뜀    |

두 번째와 세 번째는 같이 고쳐야 했습니다. 재시도만 넣으면 그 전까지의 결과가 메모리에만 있어서, 재시도까지 실패했을 때 전부 잃게 됩니다.

## 4. 코드를 읽다가 알게 된 것 — 목표 벡터를 얼마나 자주 뽑는가

STEVE-1은 지시문을 그대로 쓰지 않고, **목표 벡터**로 바꿔서 정책에 넘깁니다. 이 변환을 하는 prior에는 무작위성이 있어서 같은 문장을 넣어도 뽑을 때마다 조금씩 다른 벡터가 나옵니다.

MineStudio 예제 코드는 정책에 글만 넘깁니다. 이 경우 `forward()` 안에서 **매 스텝마다** 목표 벡터를 새로 뽑습니다. 한 판 3000스텝이면 3000번입니다.

| 방식         | 한 판 동안 일어나는 일                          |
| ------------ | ----------------------------------------------- |
| 예제 코드    | 매 스텝(초당 20번) 목표 벡터를 새로 뽑음        |
| 이 글의 실험 | 판을 시작할 때 한 번 뽑아 끝까지 같은 벡터 사용 |

논문은 "prior로 목표를 뽑는다"고만 쓰고 빈도는 밝히지 않았습니다. 저는 한 판에 한 번 뽑는 쪽이 논문의 서술에 더 가깝다고 보고 그렇게 고정했습니다. 두 방식의 숫자 차이는 아직 비교하지 않았습니다.

같은 지시문이라도 이 설정에 따라 결과가 달라질 수 있으니, 재현하거나 비교할 때 적어 둬야 하는 변수입니다.

## 5. 평가 설정

논문 부록의 설정과 제가 쓴 설정을 나란히 적었습니다.

| 항목           | 논문 (Appendix F.2)                           | 이 글                         |
| -------------- | --------------------------------------------- | ----------------------------- |
| 한 판 길이     | 3000 timesteps (2.5분)                        | 같음                          |
| 판 수          | 조건마다 10판, 조건 간 같은 seed              | seed 0–9                      |
| Guidance scale | 글 지시문은 λ = 6.0                           | 같음                          |
| 지표           | 한 판 동안 인벤토리에 보인 아이템의 최대 개수 | 같음                          |
| 지시문         | "chop a tree", "get dirt"                     | 같음                          |
| 시작 지형      | 명시 없음                                     | forest로 고정                 |
| 목표 벡터      | 빈도 명시 없음                                | 판마다 한 번                  |
| 가중치         | 원본 저장소                                   | MineStudio가 옮겨 놓은 가중치 |

seed는 월드를 만드는 번호입니다. 같은 seed면 같은 지형에서 시작하므로, 조건마다 같은 seed를 쓰면 "지형이 달라서 생긴 차이"를 빼고 비교할 수 있습니다.

시작 지형을 forest로 고정한 것은 바다나 사막 한가운데서 시작해 나무를 볼 기회조차 없는 판을 줄이기 위해서입니다. 논문에 없는 설정이라 결과를 읽을 때 감안해야 합니다.

지시문이 다른 대상을 건드리는지도 확인했습니다. "chop a tree"를 시킨 판의 흙은 평균 0.1개, "get dirt"를 시킨 판의 나무는 평균 0.2개였습니다. 시킨 것만 모았다는 뜻입니다.

"± 2.9"는 10판만 돌렸기 때문에 생기는 불확실성의 폭입니다. 같은 실험을 다시 하면 평균이 대략 2.3에서 8.1 사이에 올 것이라는 의미로 읽으면 됩니다.

## 7. 해석

- **흙은 재현됐습니다.** 10.7과 9.2는 신뢰구간이 넓게 겹칩니다.
- **지시문에 따라 수집 대상이 갈리는 성질도 재현됐습니다.** 나무를 시키면 나무만, 흙을 시키면 흙만 모았습니다.
- **나무는 논문보다 낮습니다.** 신뢰구간은 겹치지만 평균이 5.2와 약 8.5로 차이가 있습니다.

나무가 낮게 나온 이유로 생각해 본 후보입니다. 아직 확인한 것은 없습니다.

| 후보                | 근거                                                   |
| ------------------- | ------------------------------------------------------ |
| 판별 분산           | 10판 중 3판이 0–2개. 판 수가 적어 평균이 흔들림        |
| 목표 벡터 뽑는 빈도 | 4절의 설정 차이                                        |
| 가중치 이식         | 원본이 아니라 MineStudio가 옮긴 가중치를 사용          |
| 시작 조건           | forest로 고정했지만 seed마다 나무의 밀도와 거리가 다름 |

## 8. 정리

- 공개 가중치와 논문 부록의 설정만으로 20판을 돌려, 흙 수집량과 지시문에 따른 행동 분리를 재현했습니다.
- 나무 수집량은 논문보다 낮았고, 원인은 좁히지 못했습니다.
- 논문에 적히지 않은 설정(시작 지형, 목표 벡터를 뽑는 빈도)이 있어서, 재현할 때는 무엇을 어떻게 정했는지 같이 적어야 합니다.
- 다음 글에서는 STEVE-1 이후에 나온 논문 세 편을 읽고, 무엇을 실험할지 정합니다.
