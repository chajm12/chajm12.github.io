> **이 글에 대해**
> [STEVE-1 논문 정리]({% post_url 2026-11-17-steve1-text-to-behavior %})에서 읽기만 했던 모델을 직접 실행한 기록입니다.
> 지시문을 바꿔 보는 실험을 하기 전에, 먼저 논문과 같은 조건에서 같은 숫자가 나오는지 확인했습니다.
> 기준점이 맞아야 그 뒤의 비교를 믿을 수 있기 때문입니다.

## 1. 한눈에

| 항목      | 내용                                                            |
| --------- | --------------------------------------------------------------- |
| 모델      | STEVE-1 공개 가중치 (`CraftJarvis/MineStudio_STEVE-1.official`) |
| 실행 도구 | [MineStudio](https://github.com/CraftJarvis/MineStudio) 1.1.6   |
| 장비      | 클라우드 GPU (H100 1장)                                         |
| 평가 방식 | 논문 Appendix F.2 · Table 3                                     |
| 규모      | 지시문 2개 × 10판 = 20판, 약 38분                               |
| 결과      | 흙 10.7개 (논문 9.2), 나무 5.2개 (논문 약 8.5)                  |

학습은 하지 않았습니다. 공개된 가중치를 그대로 불러와 게임을 시키고 결과만 셌습니다. 그래서 여기서 나오는 숫자는 "모델이 얼마나 잘 배웠나"가 아니라 "이미 학습된 모델이 이 지시문을 받았을 때 무엇을 하나"를 잰 것입니다.

## 2. 실행 환경

STEVE-1 원본 저장소 대신 MineStudio를 썼습니다. 시뮬레이터, 모델, 가중치 내려받기를 한 패키지로 묶어 둔 도구라 설치가 간단합니다.

| 구성      | 설정                                     |
| --------- | ---------------------------------------- |
| Python    | 3.10 (conda)                             |
| Java      | 8 (OpenJDK). 마인크래프트 실행에 필요    |
| 화면      | `xvfb-run`으로 가상 디스플레이 사용      |
| 관측 크기 | 128 × 128                                |
| 실행      | `nohup`으로 백그라운드 실행, 로그는 파일 |

모니터가 없는 서버라 게임 화면을 그릴 곳이 없습니다. `xvfb-run`은 가짜 모니터를 만들어 주는 명령입니다. `nohup`은 접속을 끊어도 프로그램이 계속 돌게 합니다. 노트북을 덮어도 실험은 서버에서 이어집니다.

작업 흐름은 단순합니다. 스크립트는 노트북에서 쓰고, 서버로 보내 실행하고, 결과 파일과 영상만 다시 가져옵니다.

한 판 동안 일어나는 일을 [논문 정리 글]({% post_url 2026-11-17-steve1-text-to-behavior %})의 용어로 적으면 이렇습니다.

```text
판을 시작할 때   지시문 → MineCLIP 글 인코더 → prior → 목표 벡터 (512차원)
매 스텝 (1/20초) 화면 128×128 + 목표 벡터 → STEVE-1 → 키보드 · 마우스 → 게임
```

가중치는 고정이고, 판과 판 사이에 기억은 없습니다. 앞 판에서 잘했다고 다음 판에서 더 잘하지 않습니다.

## 3. 첫 실행 — 짧게 돌려서 되는지부터 확인

20판을 한꺼번에 돌리기 전에 600스텝(30초 분량)짜리 한 판을 먼저 돌렸습니다.

| 항목      | 값                                                              |
| --------- | --------------------------------------------------------------- |
| 지시문    | "chop a tree"                                                   |
| 설정      | 600스텝, forest 시작, seed 0                                    |
| 결과      | 자작나무 원목(`birch_log`) 5개                                  |
| 영상      | 나무 쪽으로 걸어가 캐는 장면 확인                               |
| 걸린 시간 | 시작까지 530초 (가중치와 게임 엔진 내려받기), 600스텝은 약 25초 |

처음 실행은 내려받기 때문에 9분 가까이 걸렸습니다. 한 번 받은 뒤로는 바로 시작합니다. 영상에서 에이전트가 실제로 나무를 찾아가 캐는 것을 보고 나서야 본 실험으로 넘어갔습니다. 숫자만 보고 넘어갔다면 인벤토리를 잘못 읽고 있어도 몰랐을 것입니다.

## 4. 한 판을 돌리는 코드

뼈대는 아래와 같습니다.

```python
policy = SteveOnePolicy.from_pretrained("CraftJarvis/MineStudio_STEVE-1.official").to("cuda").eval()
env = MinecraftSim(obs_size=(128, 128), preferred_spawn_biome="forest", callbacks=[])

env.env.seed(seed)
obs, info = env.reset()
cond = policy.prepare_condition({"cond_scale": 6.0, "text": "chop a tree"})  # 판마다 한 번
memory = None
for _ in range(3000):
    x = {"image": torch.from_numpy(obs["image"])[None, None].to("cuda"), "condition": cond}
    action, memory = policy.get_action(x, memory, input_shape="BT*")
    action = {k: v[0][0] for k, v in action.items()}
    obs, reward, terminated, truncated, info = env.step(action)
```

### 무엇을 세는가

매 스텝 인벤토리를 읽어 나무와 흙의 개수를 세고, 그 판에서 본 **최대값**을 기록합니다.

```python
def count_items(inventory, predicate):
    total = 0
    for slot in inventory.values():
        if isinstance(slot, dict) and predicate(str(slot.get("type", ""))):
            total += int(slot.get("quantity", 0))
    return total

def is_log(t):
    return t.endswith("_log") or t == "log"   # oak_log, birch_log 등 나무 종류를 모두 합침

# 매 스텝
max_log = max(max_log, count_items(info["inventory"], is_log))
```

판이 끝났을 때의 개수가 아니라 최대값을 쓰는 것은 논문의 지표가 그렇기 때문입니다. 이렇게 하면 캔 나무를 중간에 판자로 만들거나 떨어뜨린 판도 캔 만큼 셉니다.

결과는 한 판이 끝날 때마다 CSV 파일에 한 줄씩 씁니다. 평균과 신뢰구간은 이 파일을 읽는 별도 스크립트로 계산했습니다.

## 5. 막혔던 곳

| 증상                                | 원인                                                                                      | 대응                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 백그라운드 실행이 시작하자마자 종료 | 게임 엔진이 임시 저장소에 있어 서버를 멈추면 사라짐. 다시 받을지 묻는 `Y/N` 입력에서 멈춤 | `MINESTUDIO_DIR`을 지워지지 않는 저장소로 지정하고 엔진을 미리 내려받음 |
| 13번째 판에서 `TimeoutError`        | 새 월드를 만드는 `env.reset()`에서 게임이 응답하지 않음                                   | 다시 실행해 끝난 판은 건너뛰고 이어서 진행. 이후 자동 재시도를 추가     |
| 중간에 끊기면 결과가 사라질 위험    | 결과를 마지막에 한 번에 저장                                                              | 한 판이 끝날 때마다 CSV에 한 줄 기록, 다시 실행하면 끝난 판은 건너뜀    |
| 어느 판의 영상인지 알 수 없음       | 기본 녹화 기능은 판 번호로만 저장                                                         | `seed0_once_lam6_chop_a_tree.mp4`처럼 조건을 파일 이름에 넣어 직접 저장 |

첫 번째는 원인을 찾는 데 가장 오래 걸렸습니다. 백그라운드로 돌린 프로그램은 키보드 입력을 받을 수 없어서, 화면에는 아무것도 안 보이고 로그 파일 끝에 `Y/N` 질문만 남아 있었습니다.

두 번째 오류는 20판 중 12판을 끝낸 뒤에 났습니다. 판마다 결과를 써 두었기 때문에 12판은 남아 있었고, 같은 명령을 다시 실행해 13번째 판부터 이어 갔습니다. 같은 오류가 다음 실험에서도 나와서, 그때 오류가 나면 게임을 닫고 새로 띄워 그 판만 다시 시도하는 기능을 넣었습니다.

```python
for attempt in range(1, max_retries + 1):
    try:
        row = run_episode(env, prompt, seed)
        break
    except Exception as e:                     # 시뮬레이터가 멈춘 경우 등
        print(f"[error] seed={seed} attempt {attempt}: {type(e).__name__}")
        env.close()
        os.system("pkill -9 -f java")          # 남아 있는 게임 프로세스 정리
        time.sleep(10)
        env = make_env()                       # 시뮬레이터를 새로 만든다
```

이 기능은 GPU를 켜기 전에 가짜 시뮬레이터로 먼저 시험했습니다. 일부러 시간 초과를 일으켜서 재시도, 포기, 이어서 실행이 순서대로 되는지 확인했습니다. GPU 시간은 돈이라, 서버에서 처음 돌려 보며 고치는 일을 줄이고 싶었습니다.

## 6. 코드를 읽다가 알게 된 것 — 목표 벡터를 얼마나 자주 뽑는가

STEVE-1은 지시문을 그대로 쓰지 않고, **목표 벡터**로 바꿔서 정책에 넘깁니다. 이 변환을 하는 prior에는 무작위성이 있어서 같은 문장을 넣어도 뽑을 때마다 조금씩 다른 벡터가 나옵니다.

MineStudio 예제 코드는 정책에 글만 넘깁니다. 이 경우 정책의 `forward()` 안에서 **매 스텝마다** 목표 벡터를 새로 뽑습니다. 아래는 해당 부분을 요약한 것입니다.

```python
# SteveOnePolicy.forward (MineStudio 1.1.6) 요약
condition = input["condition"].copy()
if "mineclip_embeds" not in condition:              # 글만 넘긴 경우
    condition = self.prepare_condition(condition)   # 매 스텝 호출된다

# prepare_condition 안에서
#   text_embeds = mineclip.encode_text(texts)
#   mineclip_embeds = self.prior(text_embeds, deterministic=False)   ← 뽑을 때마다 다름
```

| 방식         | 한 판 동안 일어나는 일                          |
| ------------ | ----------------------------------------------- |
| 예제 코드    | 매 스텝(초당 20번) 목표 벡터를 새로 뽑음        |
| 이 글의 실험 | 판을 시작할 때 한 번 뽑아 끝까지 같은 벡터 사용 |

논문은 "prior로 목표를 뽑는다"고만 쓰고 빈도는 밝히지 않았습니다. 저는 한 판에 한 번 뽑는 쪽이 논문의 서술에 더 가깝다고 보고 그렇게 고정했습니다. 스크립트에는 두 방식을 고르는 옵션을 넣어 두었지만, 두 방식의 숫자 차이는 아직 비교하지 않았습니다.

두 방식은 실패하는 모양이 다를 것으로 예상합니다.

- **한 판에 한 번**: 운 나쁘게 엉뚱한 목표 벡터가 뽑히면 그 판 전체가 영향을 받습니다. 판마다 결과가 크게 갈릴 수 있습니다.
- **매 스텝**: 목표가 계속 조금씩 흔들리지만, 여러 번 뽑으니 평균에 가까워집니다.

같은 지시문이라도 이 설정에 따라 결과가 달라질 수 있으니, 재현하거나 비교할 때 적어 둬야 하는 변수입니다.

## 7. 평가 설정

논문 부록의 설정과 제가 쓴 설정을 나란히 적었습니다.

| 항목           | 논문 (Appendix F.2)                           | 이 글                         |
| -------------- | --------------------------------------------- | ----------------------------- |
| 한 판 길이     | 3000 timesteps (2.5분)                        | 같음                          |
| 판 수          | 조건마다 10판, 조건 간 같은 seed              | seed 0–9                      |
| Guidance scale | 글 지시문은 λ = 6.0                           | 같음                          |
| 지표           | 한 판 동안 인벤토리에 보인 아이템의 최대 개수 | 같음                          |
| 지시문         | "chop a tree", "get dirt"                     | 같음                          |
| 시작 지형      | 명시 없음                                     | forest로 고정                 |
| 목표 벡터      | 빈도 명시 없음                                | 판마다 한 번                  |
| 가중치         | 원본 저장소                                   | MineStudio가 옮겨 놓은 가중치 |

- **seed**는 월드를 만드는 번호입니다. 같은 seed면 같은 지형에서 시작하므로, 조건마다 같은 seed를 쓰면 "지형이 달라서 생긴 차이"를 빼고 비교할 수 있습니다.
- **λ**(guidance scale)는 목표를 얼마나 강하게 따르게 할지 정하는 값입니다. 클수록 지시를 더 강하게 따릅니다.
- **시작 지형을 forest로 고정**한 것은 바다나 사막 한가운데서 시작해 나무를 볼 기회조차 없는 판을 줄이기 위해서입니다. 논문에 없는 설정이라 결과를 읽을 때 감안해야 합니다.

### ± 값을 읽는 법

"5.2 ± 2.9"는 10판 평균이 5.2이고, 판을 10번만 돌렸기 때문에 생기는 불확실성의 폭이 2.9라는 뜻입니다. 같은 실험을 다시 하면 평균이 대략 2.3에서 8.1 사이에 올 것으로 읽으면 됩니다.

```text
폭 = t × (표준편차 ÷ √판 수)        판 수가 10이면 t ≈ 2.26

"chop a tree":  표준편차 4.08 → 2.26 × 4.08 ÷ √10 ≈ 2.9
```

판마다 결과가 들쭉날쭉할수록, 그리고 판 수가 적을수록 폭이 커집니다.

평균만 보면 놓치는 것이 있습니다. 같은 지시문인데도 나무는 0개에서 12개까지, 흙은 2개에서 25개까지 퍼져 있습니다. 가중치도 지시문도 같으니, 이 차이는 시작 월드와 행동을 뽑을 때의 무작위성에서 옵니다.

나무 평균을 끌어내린 것은 0–2개에 그친 세 판입니다. 반대로 11개, 12개를 모은 판도 있습니다. "평균 5.2개를 모으는 모델"이라기보다 "잘 풀리는 판과 안 풀리는 판이 갈리는 모델"에 가깝습니다.

### 걸린 시간

20판에 약 38분이 걸렸습니다. 처음 12판에 23.6분, 오류 뒤 나머지 8판에 13.9분입니다. 한 판(게임 시간 2.5분)에 실제로 약 2분이 걸립니다.

## 9. 해석

- **흙은 재현됐습니다.** 10.7과 9.2는 신뢰구간이 넓게 겹칩니다.
- **지시문에 따라 수집 대상이 갈리는 성질도 재현됐습니다.** 나무를 시키면 나무만, 흙을 시키면 흙만 모았습니다.
- **두 지시 모두 목표를 주지 않은 VPT보다 높습니다.** 지시문이 실제로 행동을 바꾸고 있다는 뜻입니다.
- **나무는 논문보다 낮습니다.** 신뢰구간은 겹치지만 평균이 5.2와 약 8.5로 차이가 있습니다.

나무가 낮게 나온 이유로 생각해 본 후보입니다. 아직 확인한 것은 없습니다.

| 후보                | 근거                                                   | 확인하려면                                  |
| ------------------- | ------------------------------------------------------ | ------------------------------------------- |
| 판별 분산           | 10판 중 3판이 0–2개. 판 수가 적어 평균이 흔들림        | 영상을 저장한 seed 1에서 무엇을 했는지 보기 |
| 목표 벡터 뽑는 빈도 | 6절의 설정 차이                                        | 매 스텝 방식으로 같은 10판을 다시 돌리기    |
| 가중치 이식         | 원본이 아니라 MineStudio가 옮긴 가중치를 사용          | 원본 코드로 실행 (설치 비용이 큼)           |
| 시작 조건           | forest로 고정했지만 seed마다 나무의 밀도와 거리가 다름 | seed별 영상에서 시작 위치 확인              |

논문의 나무 값이 그래프에서 눈으로 읽은 근사값이라는 점도 감안해야 합니다. 흙은 논문에 숫자가 적혀 있지만 나무는 막대 높이를 읽었습니다.

## 10. 정리

- 공개 가중치와 논문 부록의 설정만으로 20판을 돌려, 흙 수집량과 지시문에 따른 행동 분리를 재현했습니다.
- 나무 수집량은 논문보다 낮았고, 원인은 좁히지 못했습니다.
- 논문에 적히지 않은 설정(시작 지형, 목표 벡터를 뽑는 빈도)이 있어서, 재현할 때는 무엇을 어떻게 정했는지 같이 적어야 합니다.
- 실험 자체보다 실험이 끊기지 않게 만드는 일에 시간이 더 들었습니다. 판마다 결과를 저장하고 이어서 돌릴 수 있게 해 둔 것이 가장 쓸모 있었습니다.
