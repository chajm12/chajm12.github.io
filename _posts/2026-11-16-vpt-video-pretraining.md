> **이 글에 대해**
> [앞 글]({% post_url 2026-11-14-voyager-code-as-skill %})의 Voyager는 화면을 보지 않고 코드로 행동했습니다.
> VPT는 반대쪽 끝입니다. 화면(픽셀)만 보고 사람처럼 키보드와 마우스를 누릅니다. 언어는 전혀 쓰지 않습니다.
> 다음 글의 STEVE-1이 VPT를 그대로 가져다 쓰기 때문에, 읽으면서 헷갈렸던 지점을 질문 형태로 함께 정리했습니다.

## 1. 한눈에

| 항목          | 내용                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| 논문          | Video PreTraining (VPT): Learning to Act by Watching Unlabeled Online Videos                |
| 저자 · 발표   | Baker et al. (OpenAI) · NeurIPS 2022 · [arXiv 2206.11795](https://arxiv.org/abs/2206.11795) |
| 코드 · 가중치 | [openai/Video-Pre-Training](https://github.com/openai/Video-Pre-Training)                   |
| 입력          | 게임 화면 128×128 픽셀. 게임 내부 상태도, 텍스트도 없음                                     |
| 출력          | 키보드 + 마우스 입력, 초당 20회                                                             |

**한 줄 요약.** 소량의 라벨 데이터로 IDM(Inverse Dynamics Model)을 학습하고, 그 IDM이 대규모 인터넷 영상에 행동 라벨을 붙인 뒤, 그 영상으로 사람처럼 플레이하는 모델을 학습합니다.

## 2. 풀려는 문제 — 영상은 많은데 행동 라벨이 없다

글과 이미지 분야는 인터넷의 대규모 데이터로 사전학습한 모델이 표준이 됐습니다. 행동을 배우는 분야에는 그런 모델이 없었습니다.

마인크래프트 플레이 영상은 유튜브에 아주 많습니다. 하지만 영상에는 화면만 있고, 그 순간 어떤 키를 눌렀는지는 없습니다. 사람의 행동을 따라 하도록 학습(behavioral cloning, BC)하려면 "이 화면에서 이 키를 눌렀다"는 쌍이 필요한데, 그 정답이 빠져 있습니다.

## 3. 방법 — 쉬운 문제를 먼저 풀어 라벨을 만든다

| 단계                     | 하는 일                                                      | 데이터                               |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------ |
| 1. Contractor data 수집  | 사람을 고용해 플레이를 녹화. 화면과 실제 키 입력을 함께 기록 | 약 2천 시간                          |
| 2. IDM 학습              | 앞뒤 프레임을 보고 그 사이에 누른 키를 맞히는 모델 학습      | 1번 데이터                           |
| 3. Pseudo-labeling       | IDM이 인터넷 영상에 행동 라벨을 추정해서 붙임                | 27만 시간 수집 → 정제 후 약 7만 시간 |
| 4. Foundation model 학습 | 라벨이 붙은 영상으로 BC. 과거 프레임만 보고 다음 행동을 예측 | 3번 데이터                           |

IDM의 정확도는 키 입력 90.6%, 마우스 움직임은 R² 0.97입니다. 사람이 기록한 진짜 정답은 2천 시간뿐인데, 최종 모델은 그 35배인 7만 시간으로 학습했습니다.

최종 모델은 파라미터 약 5억 개이고, V100 GPU 720개로 9일 동안 학습했습니다.

## 4. 읽으며 헷갈렸던 것들

### 라벨은 어떻게 생겼나

"나무 캐기" 같은 의미가 적혀 있지 않습니다. 프레임마다 어떤 입력이 눌렸는지만 있습니다.

```text
frame 1:  forward(W) = 1,   camera = (+1, 0)
frame 2:  forward(W) = 1,   camera = ( 0, 0)
frame 3:  attack(LMB) = 1,  camera = ( 0, 0)
frame 4:  attack(LMB) = 1,  camera = ( 0, 0)
frame 5:  attack(LMB) = 1,  camera = ( 0,-1)
  …  (1초 = 20프레임)
```

Voyager에서는 `mineBlock(bot, "oak_log", 3)` 한 줄에 의미가 담겨 있었습니다. VPT에서는 같은 행동이 의미 없는 프레임 단위 입력 수백 개로 흩어져 있습니다. 모델은 "나무를 캔다"는 것을 모르고, 그런 화면에서 사람이 보통 무엇을 누르는지만 배웁니다.

행동 공간은 사람의 인터페이스 그대로입니다.

| 종류        | 예                                                |
| ----------- | ------------------------------------------------- |
| 키보드      | W·A·S·D, 점프, 달리기, 핫바 1–9, 인벤토리 열기    |
| 마우스 버튼 | attack(왼쪽), use(오른쪽)                         |
| 카메라      | 좌우 · 상하 각각 11개 구간으로 나눈 마우스 이동량 |

제작도 전용 명령이 아니라 인벤토리 창을 열고 마우스로 끌어다 놓는 방식입니다.

### IDM이 이미 행동을 맞히는데, 왜 모델을 하나 더 만드나

IDM은 **미래 프레임을 봅니다.** 그래서 라벨을 붙이는 데는 쓸 수 있지만 게임을 플레이하는 데는 쓸 수 없습니다.

```text
IDM     :  a_t ← f(o_{t-k}, …, o_t, …, o_{t+k})    과거 + 미래
Policy  :  a_t ← π(o_1, …, o_t)                    과거만
```

|             | IDM                                    | Policy (foundation model)    |
| ----------- | -------------------------------------- | ---------------------------- |
| 보는 것     | 과거 + 미래 프레임                     | 과거 프레임만                |
| 하는 일     | 이미 일어난 일을 해석                  | 다음에 할 일을 결정          |
| 배우는 단서 | 화면 변화 → 눌린 키                    | 상황 → 사람이 보통 하는 행동 |
| 난이도      | 쉬움. 적은 데이터로 충분               | 어려움. 많은 데이터가 필요   |
| 실제 플레이 | 불가. 미래 프레임은 행동한 뒤에야 생김 | 가능                         |

"나무 앞에 서 있는 사진"과 "나무에 금이 간 사진"을 함께 보여 주면 "때렸다"는 누구나 맞힙니다. 앞 사진만 보여 주고 다음 행동을 물으면 그 사람의 의도를 짐작해야 합니다. 앞의 문제가 훨씬 쉽기 때문에 적은 데이터로도 풀리고, 그 결과로 뒤의 어려운 문제에 쓸 데이터를 대량으로 만드는 것이 VPT의 핵심입니다.

### IDM에서 미래 프레임만 빼고 쓰면 안 되나

안 됩니다. IDM이 배운 단서는 "다음 프레임에서 블록의 금이 커졌으니 attack"처럼 미래 정보에 의존합니다. 실행할 때 과거만 주어진다면 학습할 때도 과거만 봐야 합니다.

### 실행할 때는 어떻게 움직이나

매 순간 모든 입력에 확률을 매기고, 그 확률에 따라 하나를 뽑습니다.

```text
화면 o_t → 이미지 인코더 → 메모리(Transformer) → 행동 확률

  forward 0.70 · attack 0.15 · jump 0.05 · …
  → 하나를 뽑음 → 게임에 입력 → 다음 화면 → 반복 (초당 20회)
```

확률이 가장 높은 것을 고르는 게 아니라 뽑기 때문에, 같은 상태에서 시작해도 매번 조금씩 다르게 움직입니다. 목표가 주어지지 않으므로 나무를 캐는 것도 "나무를 캐려고" 하는 것이 아니라 학습 데이터에서 사람들이 그렇게 많이 했기 때문입니다.

실패를 감지하는 단계는 없습니다. Reflexion은 한 판이 끝난 뒤 반성문을 쓰고 Voyager는 매번 검증하지만, VPT는 새 화면에 반응할 뿐입니다.

## 5. 결과

| 조건                              | 할 수 있는 것                                                    |
| --------------------------------- | ---------------------------------------------------------------- |
| 추가 학습 없음 (zero-shot)        | 나무 캐기, 판자와 작업대 만들기, 사냥, 수영. 나무 도구는 못 만듦 |
| BC fine-tuning (게임 초반 데이터) | 나무 · 돌 도구 제작                                              |
| RL fine-tuning                    | 10분 안에 철 곡괭이 80% 이상, 다이아몬드 곡괭이 2.5%             |
| 사전학습 없이 RL만                | 보상을 거의 받지 못해 나무 수집도 실패                           |

다이아몬드 곡괭이는 숙련된 사람도 20분 넘게, 약 24,000번의 입력이 필요한 일입니다. 사전학습 없이는 강화학습(RL)이 시작조차 되지 않았다는 마지막 줄이 사전학습이 필요한 이유입니다.

데이터 양에 따른 변화도 보고되어 있습니다. 작업대 제작은 약 5천 시간 이상에서 나타나기 시작합니다.

## 6. 함께 알아 둘 개념 두 가지

### Foundation model

대규모 데이터로 사전학습되어 여러 일을 어느 정도 해내고, 다른 일로 fine-tuning할 때 출발점이 되는 모델입니다. 글에서는 GPT, 이미지-글에서는 CLIP이 그 역할을 합니다. VPT는 행동 영역에서 같은 방식이 통한다는 것을 보였고, 실제로 STEVE-1의 출발점이 됩니다.

### KL regularization

RL로 fine-tuning할 때 보상은 "나무를 얻으면 +1"처럼 주어집니다. 이 보상만 따라가면 모델이 나무만 캐다가, 원래 할 줄 알던 제작이나 제련을 잊어버립니다. 이것을 catastrophic forgetting이라고 합니다.

VPT는 학습 중인 모델의 행동 확률이 원래 모델에서 너무 멀어지면 벌점을 줍니다.

```text
목표 = 보상의 합  −  β × KL(학습 중인 모델 ‖ 원래 모델)

같은 화면에서
  원래 모델      : forward 0.60 · attack 0.30
  학습 중인 모델 : forward 0.05 · attack 0.90   → 차이가 큼 → 벌점
```

새 과목만 공부하다가 예전 과목을 잊지 않도록 복습을 강제하는 것과 같습니다.

## 7. 공통 틀로 보면

| 항목        | 내용                                                                          |
| ----------- | ----------------------------------------------------------------------------- |
| 데이터      | Contractor data 약 2천 시간(IDM용) + 인터넷 영상 약 7만 시간(IDM이 라벨링)    |
| 입력 → 출력 | 화면 128×128 → 키보드 + 마우스, 초당 20회                                     |
| SKILL       | 신경망 가중치. 개별 기술이 따로 나뉘거나 이름 붙지 않고 가중치 안에 섞여 있음 |
| 평가        | 얻거나 만든 아이템 수. RL fine-tuning 후 다이아몬드 곡괭이 2.5%               |
| 언어적 문제 | 언어 입력이 없음. 무엇을 하라고 시킬 방법이 없음                              |

## 8. 정리

- VPT의 핵심은 두 단계 설계입니다. 쉬운 문제(IDM)로 소량의 정답을 대량의 pseudo-label로 늘리고, 그것으로 어려운 문제(policy)를 학습합니다.
- Skill은 가중치 안에 있습니다. 사람이 읽을 수도, 이름으로 꺼낼 수도 없습니다.
- 언어가 들어갈 자리가 없습니다. ALFWorld에서 본 언어와 행동의 불일치를 따질 수조차 없는 기준점입니다.

"잘 움직이지만 시킬 수 없는" 이 모델에 지시문을 받는 입력을 붙인 것이 STEVE-1입니다. [다음 글]({% post_url 2026-11-17-steve1-text-to-behavior %})에서 정리합니다.
