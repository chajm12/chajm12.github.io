> [ALFWorld 시리즈]({% post_url 2026-11-10-one-word-success-rate %})에서는 Skill이 자연어(풀이 예시, 반성문)로 표현되는 경우만 봤습니다.
> 이번 시리즈는 마인크래프트 에이전트 논문 세 편을 읽으면서, Skill이 **실행 코드**나 **신경망 가중치**로 표현될 때 무엇이 달라지는지 정리합니다.
> 첫 글은 Voyager입니다. 직접 실행하지는 않았고(GPT-4 API와 Minecraft Java Edition이 필요합니다), 논문과 공개 코드를 읽고 정리했습니다.

## 1. 왜 이 논문을 읽었나

ALFWorld에서 Reflexion을 돌리며 두 가지를 확인했습니다.

- 반성문 95개 중 실패 원인을 정확히 짚은 것은 2개였습니다. 환경이 `Nothing happens.` 한 문장만 돌려주기 때문에 반성은 추측이 됐습니다.
- 반성문은 그 게임 하나에서만 쓰입니다. 다른 게임으로 넘어가면 아무것도 남지 않습니다.

Voyager는 이 두 지점이 다르게 설계된 논문입니다. 실패 원인을 환경이 문장으로 알려 주고, 성공한 방법은 코드로 저장되어 다른 일에서도 다시 쓰입니다.

| 항목        | 내용                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| 논문        | Voyager: An Open-Ended Embodied Agent with Large Language Models                           |
| 저자 · 발표 | Wang et al. (NVIDIA 등) · TMLR 2024 · [arXiv 2305.16291](https://arxiv.org/abs/2305.16291) |
| 코드        | [MineDojo/Voyager](https://github.com/MineDojo/Voyager)                                    |
| 모델        | GPT-4 (코드 생성 · 커리큘럼 · 검증), GPT-3.5 (보조), 임베딩 모델 (검색)                    |
| 학습        | 없음. 모델 가중치는 바꾸지 않고 프롬프트와 저장된 코드만 늘어남                            |

**한 줄 요약.** GPT-4가 다음에 할 일을 스스로 제안하고, 그 일을 하는 코드를 생성 · 검증한 뒤, 통과한 코드를 skill library에 쌓으면서 계속 배웁니다.

## 2. 화면을 보지 않는다 — 관측은 텍스트, 행동은 코드

Voyager는 게임 화면(픽셀)을 보지 않습니다. [Mineflayer](https://github.com/PrismarineJS/mineflayer)라는 JavaScript 봇 라이브러리가 게임 서버와 직접 통신하고, GPT-4는 그 봇이 정리해 준 텍스트 상태만 읽습니다.

```text
Biome: forest
Time: day
Nearby blocks: oak_log, grass_block, dirt
Nearby entities: pig, chicken
Health: 20/20    Hunger: 20/20
Position: x=12, y=64, z=-30
Inventory (3/36): oak_log: 4, stick: 2
```

행동도 키보드 입력이 아니라 코드입니다. 함수 한 번 호출이 "나무 3개 캐기" 같은 의미 단위 행동 하나에 해당합니다.

```javascript
// GPT-4가 생성하는 코드의 형태 (단순화한 예시)
await mineBlock(bot, "oak_log", 3);
await craftItem(bot, "oak_planks", 3);
```

길 찾기, 시선 돌리기, 블록 캐기 같은 세부 조작은 봇이 대신 합니다. 그래서 Voyager가 다루는 문제는 "무엇을 어떤 순서로 할지"라는 계획입니다. ALFWorld처럼 텍스트를 받아 텍스트를 내놓는 구조이고, 내놓는 텍스트가 명령 한 줄이 아니라 프로그램이라는 점이 다릅니다.

## 3. 세 가지 구성 요소

| 구성 요소            | 하는 일                                                                                                  | 예                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Automatic curriculum | 현재 상태(인벤토리, 주변 블록, 위치)와 지금까지 성공 · 실패한 일의 목록을 보고 GPT-4가 다음 할 일을 제안 | 나무만 있으면 "작업대 만들기", 나무 곡괭이가 생기면 "돌 캐기" |
| Skill library        | 검증을 통과한 코드를 함수로 저장하고, 새 일을 할 때 관련 함수를 검색해 프롬프트에 넣음                   | 돌 곡괭이를 만들 때 저장해 둔 나무 곡괭이 함수를 호출         |
| Iterative prompting  | 코드를 실행하고, 피드백을 받아 고치기를 반복. 일 하나당 최대 4회                                         | 아래 세 가지 피드백을 사용                                    |

커리큘럼의 목표는 "가능한 한 다양한 것을 발견하라"입니다. 사람이 과제 목록을 주지 않아도, 현재 수준보다 조금 어려운 일이 계속 제안됩니다. 4회 안에 풀지 못한 일은 일단 접어 두고 다른 일을 받습니다.

### 세 가지 피드백

| 피드백               | 출처              | 예                                                    | ALFWorld와 비교                                    |
| -------------------- | ----------------- | ----------------------------------------------------- | -------------------------------------------------- |
| Environment feedback | 게임              | "I cannot make stick because I need: 2 more planks"   | ALFWorld는 무엇이 틀려도 `Nothing happens.`        |
| Execution error      | 코드 실행기       | 정의되지 않은 함수 호출, 문법 오류                    | `put`/`move` 같은 문법 불일치가 에러로 바로 드러남 |
| Self-verification    | 별도의 GPT-4 호출 | 일이 끝났는지 판정하고, 실패했다면 무엇을 고칠지 제안 | Reflexion의 반성문과 비슷하지만 매 시도마다 수행   |

ALFWorld에서 반성문이 원인을 짚지 못한 가장 큰 이유는 환경이 실패 이유를 말해 주지 않았기 때문입니다. Voyager는 이 정보를 세 경로로 받습니다.

## 4. Skill library — 저장 · 검색 · 조합

Skill은 실행 가능한 함수입니다. 아래는 논문 원문 코드가 아니라 구조를 보여 주기 위한 단순화 예시입니다.

```javascript
// Skill: 나무 곡괭이 만들기
async function craftWoodenPickaxe(bot) {
  await mineBlock(bot, "oak_log", 3);
  await craftItem(bot, "oak_planks", 3);
  await craftItem(bot, "stick", 1);
  await craftItem(bot, "wooden_pickaxe", 1);
}

// Skill: 돌 곡괭이 만들기 — 저장된 skill을 다시 호출한다
async function craftStonePickaxe(bot) {
  await craftWoodenPickaxe(bot);
  await mineBlock(bot, "stone", 3);
  await craftItem(bot, "stone_pickaxe", 1);
}
```

`mineBlock`, `craftItem`은 미리 주어진 기본 함수(control primitive)이고, 이것들을 조합해 GPT-4가 만든 함수가 skill입니다. 저장과 검색은 이렇게 이뤄집니다.

1. Self-verification을 통과한 코드만 저장 대상이 됩니다.
2. GPT-3.5가 그 함수의 설명문을 씁니다.
3. 설명문을 임베딩해서 벡터 DB의 key로, 코드를 value로 저장합니다.
4. 새 일이 주어지면 관련 skill 상위 5개를 검색해 프롬프트에 넣습니다.

Skill이 코드라서 생기는 성질은 네 가지입니다.

- **검증 가능**: 실행 결과로 성공 여부가 바로 확인됩니다.
- **재사용**: 다른 일, 다른 월드에서도 그대로 쓸 수 있습니다.
- **조합**: skill이 다른 skill을 호출하면서 점점 복잡한 일을 합니다.
- **해석 가능**: 사람이 읽고 고칠 수 있습니다.

## 5. 결과와 ablation

비교 대상은 마인크래프트에 맞게 옮긴 ReAct, Reflexion, AutoGPT입니다.

| 지표                       | Voyager                                                                |
| -------------------------- | ---------------------------------------------------------------------- |
| 발견한 고유 아이템         | 160회 반복 동안 63개 (비교 대상의 3.3배)                               |
| 기술 단계 도달 속도        | 나무 도구 단계 기준 최대 15.3배 빠름. 다이아몬드 단계는 Voyager만 도달 |
| 이동 거리                  | 2.3배                                                                  |
| 새 월드에서 처음 보는 과제 | 4개 모두 해결 (비교 대상은 0개)                                        |

Ablation은 구성 요소를 하나씩 빼고 성능이 얼마나 떨어지는지 보는 실험입니다.

| 뺀 것                              | 결과                                   |
| ---------------------------------- | -------------------------------------- |
| Automatic curriculum → 무작위 순서 | 발견 아이템 93% 감소                   |
| Self-verification                  | 73% 감소. 세 피드백 중 영향이 가장 큼  |
| Skill library                      | 후반으로 갈수록 성능이 정체            |
| 코드 생성을 GPT-4 → GPT-3.5        | GPT-4가 5.7배 더 많은 고유 아이템 발견 |

## 6. 한계

논문이 직접 밝힌 한계입니다.

- **비용**: GPT-4 API는 GPT-3.5보다 15배 비쌉니다.
- **Hallucination**: 커리큘럼이 게임에 없는 아이템("copper sword")을 만들자고 제안하거나, 연료가 될 수 없는 조약돌을 연료로 쓰거나, 제공되지 않은 함수를 호출합니다.
- **검증 오류**: 거미를 잡고 거미줄을 얻었는데도 성공으로 인식하지 못한 사례가 있습니다.

여기에 하나를 덧붙이면, Voyager는 픽셀이 아니라 게임 내부 상태를 직접 받습니다. 사람처럼 화면을 보고 마우스를 움직이는 조건과는 다릅니다. 이 조건을 다루는 것이 다음 글의 VPT입니다.

## 7. 공통 틀로 보면

| 항목        | 내용                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| 데이터      | 학습 데이터 없음. GPT-4를 API로 호출                                                    |
| 입력 → 출력 | 텍스트로 된 게임 상태 + 할 일 + 검색된 skill → Mineflayer API를 호출하는 코드           |
| SKILL       | 실행 가능한 함수. 검증된 것만 저장하고, 설명문 임베딩으로 검색하고, 서로 호출해 조합    |
| 평가        | 발견한 고유 아이템 수, 기술 단계 도달 속도, 새 월드에서의 과제 해결                     |
| 언어적 문제 | 실패 원인은 문장과 에러로 받음. 그래도 게임에 없는 아이템 · 함수를 지어내는 문제는 남음 |

## 8. Reflexion과 나란히 놓으면

|                    | Reflexion (직접 실행)             | Voyager (논문)                      |
| ------------------ | --------------------------------- | ----------------------------------- |
| Skill의 형태       | 자연어 반성문                     | 실행 코드                           |
| 저장하는 것        | 실패한 경험의 요약                | 검증을 통과한 성공 코드             |
| 재사용 범위        | 같은 게임의 재시도                | 다른 일, 다른 월드                  |
| 실패 신호          | `Nothing happens.` 한 문장        | 게임 메시지 + 실행 에러 + 검증 결과 |
| 관찰 · 보고된 결과 | 반성문 95개 중 원인을 짚은 것 2개 | 검증 단계를 빼면 73% 감소           |

두 방식을 가르는 것은 "실패 이유를 누가 알려 주는가"입니다. Reflexion은 모델이 추측하고, Voyager는 환경과 실행기가 알려 줍니다.

그런데 Voyager에서도 사라지지 않은 문제가 있습니다. 모델이 알고 있는 세계와 실제 게임 규칙이 다를 때 생기는 문제입니다. "구리 검"은 그럴듯하지만 그 게임에는 없습니다. ALFWorld에서 모델이 `put`을 쓴 것과 같은 유형입니다. 일상에서는 맞는 말인데 그 환경에서는 통하지 않습니다.

## 9. 정리

- Voyager는 Skill을 코드로 표현합니다. 코드는 실행으로 검증되고, 저장되고, 다시 호출됩니다.
- 실패 원인을 환경이 알려 주면 수정 능력이 크게 달라집니다. Self-verification 하나를 빼면 성능이 73% 떨어집니다.
- 언어 모델의 사전 지식과 환경 규칙이 어긋나는 문제는 Skill이 코드여도 남습니다.

[다음 글]({% post_url 2026-11-16-vpt-video-pretraining %})은 정반대 쪽에 있는 VPT입니다. 텍스트 상태도 코드도 없이, 화면만 보고 키보드와 마우스를 직접 누르는 모델입니다.
