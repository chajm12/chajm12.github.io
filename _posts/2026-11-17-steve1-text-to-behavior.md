> **이 글에 대해**
> [앞 글]({% post_url 2026-11-16-vpt-video-pretraining %})의 VPT는 잘 움직이지만 무엇을 하라고 시킬 수 없었습니다.
> STEVE-1은 VPT에 목표를 받는 입력을 추가해, 짧은 글이나 이미지로 지시할 수 있게 만든 모델입니다.
> 코드와 가중치가 공개되어 있어 이 시리즈에서 유일하게 직접 실행해 볼 수 있는 모델이기도 합니다.

## 1. 한눈에

| 항목          | 내용                                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 논문          | STEVE-1: A Generative Model for Text-to-Behavior in Minecraft                                                                   |
| 저자 · 발표   | Lifshitz et al. (University of Toronto, Vector Institute) · NeurIPS 2023 · [arXiv 2306.00937](https://arxiv.org/abs/2306.00937) |
| 코드 · 가중치 | [Shalev-Lifshitz/STEVE-1](https://github.com/Shalev-Lifshitz/STEVE-1)                                                           |
| 입력          | 게임 화면 + 목표(글 또는 이미지)                                                                                                |
| 출력          | VPT와 같은 키보드 + 마우스 입력                                                                                                 |
| 학습 비용     | 약 60달러                                                                                                                       |

**한 줄 요약.** VPT를 MineCLIP의 목표 벡터에 조건화되도록 fine-tuning해서, (지시문, 플레이 영상) 쌍을 대량으로 만들지 않고도 짧은 지시를 따르게 했습니다.

## 2. 풀려는 문제

VPT에 지시를 따르게 하려면 원래는 "이 지시문에 대해 사람이 이렇게 플레이했다"는 데이터가 대량으로 필요합니다. 사람이 영상마다 설명을 다는 일은 너무 비쌉니다.

STEVE-1은 이 라벨을 **글 대신 영상 자체에서** 만들어 냅니다.

## 3. 구조 — 이미지 생성 모델의 방식을 행동에 적용

STEVE-1은 이미지 생성 모델 DALL·E 2(unCLIP)의 구조를 그대로 가져왔습니다.

```text
DALL·E 2 :  글 → 글 벡터 → [prior] → 이미지 벡터 → [decoder] → 이미지
STEVE-1  :  글 → 글 벡터 → [prior] → 목표 벡터   → [policy]  → 키보드 · 마우스
```

Decoder 자리에 policy가 들어가고, 출력이 이미지가 아니라 행동입니다. 다음 화면은 모델이 아니라 게임이 만듭니다.

글과 영상을 같은 공간의 벡터로 바꾸는 일은 **MineCLIP**이 맡습니다. 마인크래프트 영상과 그 설명 글로 학습된 모델로, 서로 맞는 영상과 글이 가까운 벡터가 되도록 학습되어 있습니다.

|                  | MineCLIP (STEVE-1이 쓰는 방식)                | 하나의 모델에 함께 넣는 방식 (VLA 등)  |
| ---------------- | --------------------------------------------- | -------------------------------------- |
| 구조             | 영상 인코더와 글 인코더가 따로 있음           | 한 모델에 이미지와 글을 함께 입력      |
| 결과물           | 각각 512차원 벡터 하나                        | 이미지 토큰과 글 토큰이 한 줄로 이어짐 |
| 둘을 맞추는 방법 | 맞는 쌍이 가까워지도록 학습하고 벡터끼리 비교 | 모델 내부에서 서로 참조                |

이 차이는 뒤에서 한계와 연결됩니다. STEVE-1에서 글은 512차원 벡터 하나로 압축된 뒤에야 policy에 전달됩니다.

## 4. Hindsight relabeling — 도달한 장면을 나중에 목표로 삼는다

핵심 아이디어입니다. 플레이 영상을 아무 구간으로나 자르고, **그 구간의 마지막 장면**을 그 구간의 목표로 정합니다.

```text
t = 5초    나무 쪽으로 걸어감
t = 8초    나무를 치기 시작
t = 12초   나무를 얻음   ← 이 장면을 MineCLIP으로 벡터화

→ 5–12초 구간의 모든 행동에 "목표 = 12초 장면의 벡터"라는 라벨을 붙인다
```

플레이어가 실제로 그 장면에 도달했으므로, "이 목표를 향한 행동"이라는 라벨은 틀릴 수 없습니다. 사람이 글을 달 필요도 없습니다. 구간 길이는 15–200스텝(최대 약 10초)에서 무작위로 정합니다.

VPT의 pseudo-labeling과 헷갈리기 쉬워서 나란히 놓았습니다.

|              | Pseudo-labeling (VPT)        | Hindsight relabeling (STEVE-1)   |
| ------------ | ---------------------------- | -------------------------------- |
| 붙이는 것    | 행동 라벨 (어떤 키를 눌렀나) | 목표 라벨 (어디에 도달하려 했나) |
| 만드는 방법  | IDM 모델이 추정              | 규칙으로 정함 (구간의 끝 장면)   |
| 틀릴 수 있나 | 있음 (약 90% 정확)           | 없음 (실제로 도달한 장면)        |

정리하면 STEVE-1의 학습 데이터에는 세 종류의 정보가 있습니다.

| 정보                    | 있나 | 출처                                        |
| ----------------------- | ---- | ------------------------------------------- |
| 행동 (어떤 키를 눌렀나) | 있음 | 사람이 플레이한 기록 + VPT가 플레이한 기록  |
| 목표 벡터               | 있음 | 영상에서 자동 생성                          |
| 글 지시문               | 없음 | 비용 때문에 만들지 않고, 목표 벡터로 대신함 |

## 5. 학습은 두 번

|             | 1단계: Policy fine-tuning                | 2단계: Prior 학습                            |
| ----------- | ---------------------------------------- | -------------------------------------------- |
| 학습하는 것 | VPT 전체 + 목표를 받는 층                | 글 벡터를 목표 벡터로 바꾸는 작은 모델(CVAE) |
| 데이터      | 영상 구간 + hindsight 목표 + 기록된 행동 | 글–영상 쌍 약 2천 개 + GPT-3.5로 늘린 지시문 |
| 글을 쓰나   | 쓰지 않음                                | 씀                                           |

목표 벡터는 화면에서 뽑은 특징에 **더해져서** 들어갑니다.

```text
화면 o_t → 이미지 인코더 → 화면 특징 ─┐
                                      (+) → 메모리(Transformer) → 행동 확률
목표 벡터 g → 변환 층(학습됨) ────────┘
```

Policy는 글을 한 번도 보지 않고 학습됩니다. 학습할 때 받은 목표는 실제 영상의 벡터이고, 실행할 때 받는 목표는 prior가 글에서 만들어 낸 벡터입니다. 둘 다 같은 공간에 있으므로 policy는 구분하지 못합니다. 글 데이터는 2단계의 작은 모델에만 필요해서 2천 쌍으로 충분했습니다.

## 6. 실행 — 글이 행동이 되기까지

```text
① 지시문        "chop a tree"
                  │ MineCLIP 글 인코더
② 글 벡터       512차원
                  │ prior
③ 목표 벡터     512차원  ("나무를 얻은 직후 장면"과 비슷한 벡터)
                  │ 한 번만 계산하고, 그 판이 끝날 때까지 고정
④ 매 1/20초     화면 특징 + 목표 벡터 → 메모리
                  │
⑤ 행동          확률에서 하나를 뽑아 게임에 입력 → ④로
```

목표 벡터는 "다음 화면이 어떨지"에 대한 예측이 아닙니다. "어떤 상태에 도달해야 하는지"를 나타내고, 한 판 동안 바뀌지 않습니다.

> **덧붙임 (2026-11-22).** "한 번만 계산하고 고정"은 제가 논문을 읽고 이해한 방식입니다. 논문에는 목표 벡터를 얼마나 자주 뽑는지 적혀 있지 않습니다. 직접 실행해 보니 MineStudio의 예제 코드는 매 스텝 목표 벡터를 새로 뽑고 있었습니다. prior에는 무작위성이 있어서, 이 차이는 결과에 영향을 줄 수 있습니다. 자세한 내용은 [재현 글의 6절]({% post_url 2026-11-22-steve1-baseline-reproduction %})에 적었습니다.

글 대신 목표 이미지를 직접 넣을 수도 있습니다. 이 경우 prior를 거치지 않습니다. 논문에서는 이미지로 지시했을 때가 글로 지시했을 때보다 대체로 성능이 좋았습니다.

### Classifier-free guidance

학습할 때 10% 확률로 목표를 비우고 학습합니다. 그러면 모델 하나가 "목표가 있을 때"와 "없을 때"의 행동을 모두 압니다. 실행할 때는 두 결과의 차이를 키워서 목표를 더 강하게 따르게 합니다.

```text
최종 = (1 + λ) × 목표가 있을 때  −  λ × 목표가 없을 때

  목표가 있을 때 : attack 0.40
  목표가 없을 때 : attack 0.20     → attack이 더 강해짐
```

λ를 0에서 최적값으로 올리면 흙 수집이 7.5배, 나무 수집이 15배가 됩니다.

### Prompt chaining

STEVE-1은 약 10초 단위의 목표로 학습했기 때문에 긴 일을 스스로 쪼개지 못합니다. 지시를 순서대로 나눠 주면 달라집니다.

| 지시                              | 탑 쌓기 성공률 |
| --------------------------------- | -------------- |
| "build a tower" 하나만            | 약 0%          |
| "get dirt" 다음에 "build a tower" | 약 50%         |

긴 일을 하려면 위에서 일을 쪼개 주는 계획 담당(사람 또는 LLM)이 필요하다는 뜻입니다.

## 7. 결과

- 게임 초반 과제 13개 중 12개를 수행합니다.
- 목표를 받지 않는 VPT와 비교하면 흙 수집 75배, 나무 수집 4.9배입니다.

## 8. 한계 — 지시문 표현에 민감하다

이 글에서 가장 눈여겨본 부분입니다. 같은 "흙 모으기"라도 지시문을 어떻게 쓰느냐에 따라 결과가 크게 달라집니다.

| 지시문                                 | 모은 흙 (평균) |
| -------------------------------------- | -------------- |
| "get dirt"                             | 9.2            |
| 길고 구체적인 지시문                   | 26.7           |
| "break a flower" (다른 일을 시킨 경우) | 0.7            |

짧게 말했을 때와 자세히 말했을 때가 약 2.9배 차이 납니다. ALFWorld 실험에서 지시문의 동사 하나(`put` → `move`)가 성공률을 45%에서 80%로 바꾼 것과 같은 모양입니다.

> **덧붙임 (2026-11-24).** 이 민감도를 직접 확인했습니다. 나무 모으기를 여덟 가지 문장으로 시켰더니 "cut down a tree"는 평균 6.0개, "get wood"는 0.4개였습니다. 결과는 [같은 뜻, 다른 문장]({% post_url 2026-11-24-steve1-instruction-pilot %})에 있습니다.

그 밖의 한계입니다.

- **짧은 일만 가능**: 약 2분 30초 안에 끝나는 일로 한정됩니다. 다이아몬드나 집 짓기는 못 합니다.
- **Goal misgeneralization**: "punch a cow"라고 하면 가장 가까운 다른 동물을 때리는 경우가 있습니다. 때리는 능력은 있는데 대상이 틀립니다. ALFWorld에서 모델이 cloth를 towel로 착각한 것과 같은 유형입니다.
- **글이 이미지보다 약함**: 글은 prior를 한 번 더 거치기 때문으로 보입니다.
- **실패 신호 없음**: VPT와 마찬가지로 실패를 감지하거나 말로 표현하는 단계가 없습니다.

## 9. 공통 틀로 보면

| 항목        | 내용                                                                                |
| ----------- | ----------------------------------------------------------------------------------- |
| 데이터      | 사람 플레이 기록 + VPT 플레이 기록, 합쳐서 약 750시간. Prior용 글–영상 쌍 약 2천 개 |
| 입력 → 출력 | 화면 + 목표 벡터(글 또는 이미지에서 생성) → 키보드 + 마우스                         |
| SKILL       | 목표에 조건화된 신경망 가중치. 기술은 가중치 안에 있지만 목표로 골라 쓸 수 있음     |
| 평가        | 게임 초반 과제 13개의 수행 여부와 수집량                                            |
| 언어적 문제 | 지시문 표현에 따른 성능 차이, 대상 착각, 실패를 표현할 수단이 없음                  |

## 10. 정리

- STEVE-1은 글 라벨 없이 지시를 따르는 모델을 만들었습니다. 영상의 끝 장면을 목표로 삼는 hindsight relabeling이 핵심입니다.
- Policy는 글을 직접 읽지 않습니다. 글은 512차원 벡터 하나로 바뀐 뒤 화면 특징에 더해집니다.
- 그래서 같은 일을 어떤 문장으로 시키느냐가 성능을 좌우합니다. Skill이 가중치여도, 그 skill을 고르는 것은 여전히 언어입니다.
